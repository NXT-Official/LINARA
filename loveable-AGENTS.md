# Agent Notes

Read `ARCHITECTURE.md` before making structural changes. Short version of the rules:

## Tooling

- **Bun is the package manager.** Use `bun install`, `bun run <script>`. Never generate a
  `package-lock.json` / `pnpm-lock.yaml`; `bun.lock` is the only lockfile.
- Before calling work done, run: `bun run lint`, `bun run typecheck`, `bun run build`.
  `bun run format` fixes Prettier issues (Prettier is enforced through ESLint).
- Don't add dependencies for something a few lines of code or an already-installed package
  covers. Every direct dependency ships to users.

## TanStack Start conventions

- File-based routing under `src/routes/` — see `src/routes/README.md` for the URL mapping.
  Don't invent `src/pages/` or `app/` directories.
- `src/routeTree.gen.ts` is generated by the router plugin on `dev`/`build`. Never edit it by
  hand; it is committed so typecheck works on a fresh clone.
- Entries are resolved by convention from `src/`: `router.tsx`, `start.ts`, `server.ts`, and
  `routes/__root.tsx`. Don't add `main.tsx` / `entry-client.tsx` / `entry-server.tsx`.
- Preserve existing route URLs and the `<Outlet />` in `__root.tsx`.
- Hooks must run unconditionally — put early `return null` guards _after_ all hook calls.

## Server / client boundary

- Anything imported by a route component ends up in the browser bundle. Server-only work
  belongs in `createServerFn` or a `*.server.ts` module (the ESLint config blocks the Next.js
  `server-only` package for this reason).
- Client-visible env vars must be prefixed `VITE_`; anything without that prefix stays on the
  server. Keep the two sets disjoint.

## Secrets

- No keys, tokens, or credentials in source, Markdown, or committed config. `.env` is
  gitignored; document new variables by name only in `.env.example`.
